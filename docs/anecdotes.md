# 실측 노트 — 문서로는 알 수 없었던 것들

이 프로젝트를 만들면서 **직접 두드려 보고 나서야 알게 된 것**만 모았다. 대부분은 「그럴 것이다」라고
가정했다가 틀린 것들이고, 몇 개는 그대로 뒀으면 조용히 틀린 답을 내보냈을 것들이다.

각 항목은 `발견 → 증거 → 그래서 코드가 어떻게 됐나` 순이다. 날짜는 실호출한 날이다.
설계 근거는 [mcp-draft.md](mcp-draft.md) 로드맵 절에, 규칙은 [CLAUDE.md](../CLAUDE.md) 에 있다.

## 1. 접수번호로 DART 를 열면 **다른 회사 공시**가 나온다 (2026-09-07)

핸드오프 문서에 「DART 링크가 틀렸다」고만 적혀 있어서 직접 확인했다.

```
삼성전자 기업지배구조보고서 접수번호  20250530001005
  KIND  → 삼성전자 기업지배구조 보고서 공시          ✅
  DART  → 에이치솔루션 「대규모기업집단현황공시」     ❌ 완전히 다른 회사
```

KIND(거래소)와 DART(금감원)는 접수번호 체계가 별개다. 번호가 우연히 유효해서 **404 가 아니라 엉뚱한
문서가 200 으로 열린다** — 링크를 눌러보기 전엔 아무도 모른다.

→ `services/reports.py` 의 `DART_URL` 을 제거했다. 도구 설명에도 「KIND 접수번호」로 명시.

## 2. 「왜 미준수인가」는 비고란에 없다 (2026-09-07)

지배구조 핵심지표 15개 표에는 「비고」 열이 있다. 당연히 거기 사유가 있을 줄 알았다.

```
삼성전자 2024·2025·2026 세 보고서 — 비고 15칸 × 3년 = 45칸이 전부 비어 있음
실제 사유는 각 세부원칙의 「(1) 미진한 부분 및 그 사유」에:
  1-4 「…배당 관련 예측가능성을 제고하는 방안을 검토 하겠습니다」
  7-2 「개별이사별 활동내역 공개 관련하여 영업 상의 비밀로 인하여 공개하지 못하고 있었습니다」
```

핸드오프 계획대로 비고를 읽었으면 **빈 도구**가 나왔을 것이다.

→ `scope="notes"` 는 원칙 블록의 사유·계획을 읽는다.

## 3. KIND 원문은 한 번에 안 온다 — 3단이고, 접수번호 ≠ 문서번호 (2026-09-07)

```
① disclsviewer.do?method=search&acptno=20250530001005
     → <select id="mainDoc"> 안에 문서번호 20250530001923   ← 접수번호와 다르다
② disclsviewer.do?method=searchContents&docNo=20250530001923
     → 본문이 아니라 parent.setPath('…_toc.htm','…/99667.htm',…) 한 줄
③ external/2025/05/30/001005/20250530001923/99667.htm      → 본문 5.7MB
```

②를 건너뛸 수 없다. 본문 주소 끝의 **서식번호를 응답에서만 알 수 있기** 때문이다.

**서식번호가 곧 문서 종류다:**

| 번호 | 문서 |
|---|---|
| `99667` | 기업지배구조보고서 |
| `99669` | 금융회사 지배구조 연차보고서 |
| `61979` | 지속가능경영보고서 등 관련사항(자율공시) |
| `99998` | 기타공개첨부서류 — 여기 PDF 본체가 걸린다 |

## 4. 금융회사는 원문을 받기 **전에** 걸러낼 수 있다 (2026-09-07)

KB금융의 지배구조보고서를 열었더니 5.7KB 짜리 안내문뿐이었다. 세부원칙이 하나도 없다 —
금융회사는 「금융회사 지배구조 연차보고서」로 갈음하기 때문이고, 내용은 첨부 PDF 에 있다.

다행히 KRX 공시 목록의 **제목 접미사**가 신호였다: 「기업지배구조 보고서 공시**(연차보고서)**」.

→ 목록 제목만 보고 `no_data` 로 끊는다. 5~12MB 를 받아 파싱한 뒤 0건을 확인하는 낭비가 없다.
   서식번호 `99669` 와 **독립된 두 번째 신호**라 하나가 바뀌어도 다른 하나가 잡는다.

## 5. 자유편집 표 하나가 3.7MB (2026-09-07)

삼성전자 지배구조보고서 본문이 5.7MB, 2024년판은 11.9MB였다. 이미지 때문인 줄 알고 base64 를 찾았는데
하나도 없었다. 범인은 **엑셀에서 붙여넣은 미등기 임원 명단** — 세부원칙 4-4 한 곳에 1,127행이,
행마다 인라인 스타일이 통째로 붙어 3.7MB였다.

→ 이 표는 `aclass` 가 `krx-cg_` 가 아니라 **서식 표가 아니다**(회사 자유편집). 파서가 무시한다.
   fixture 를 만들 때도 이 블록만 들어냈다(3.8MB → 98KB).

## 6. 한글 자간 공백이 **PDF 안에 박혀 있다** (2026-09-07)

지속가능경영보고서에서 「온실가스배출량」을 찾으면 **0쪽**이 나온다. 실제로는 16쪽에 있다.

```
원문 추출 결과:  「온실가스 배출량」 「세 계 접근 성 인 식의 날」
```

처음엔 파서 탓인 줄 알고 `x_tolerance` 를 2·3·4·5 로 바꿔 봤다 — **278건 그대로**였다. 파서 문제가
아니라 디자이너가 자간을 벌려 조판해서 공백이 실제로 들어 있는 것이다. 엔진을 바꿔도 안 없어진다
(pypdfium2 898 · pdfplumber 853 · pypdf 1,854건).

```
온실가스배출량   그대로  0쪽  →  공백무시 16쪽
중대성평가       그대로  0쪽  →  공백무시  3쪽
사업장폐기물     그대로  0쪽  →  공백무시  5쪽
```

→ 검색은 **반드시** 공백을 지우고 한다. 발췌는 원문 표기로 보여주려고 공백 제거본과 원문의
   위치 대응표를 들고 다닌다. 이걸 안 하면 있는 내용이 「없음」으로 나가는데, 아무도 눈치채지 못한다.

## 7. pypdf 는 숫자 안에 공백을 넣는다 (2026-09-07)

```
원문      567,056
pypdf     567 ,056     ← 87쪽 문서에서 56건
pdfplumber / pypdfium2  567,056  ← 0건
```

숫자를 보여주는 도구에서 이건 치명적이다. **틀린 값을 조용히 내보낸다.**

→ pypdf 를 쓰지 않는다. 훑기는 pypdfium2, 표 정렬은 pdfplumber.

## 8. pypdfium2 가 pdfplumber 보다 **48배** 빠르다 (2026-09-07)

87쪽 4MB 문서 전체 텍스트 추출:

| 엔진 | 시간 |
|---|---|
| pypdfium2 | **0.3초** |
| pypdf | 7.2초 |
| pdfplumber | 14.5초 |

→ 두 엔진을 나눠 쓴다. 「어느 쪽에 있나」는 pypdfium2(0.3초), 「그 쪽을 보여줘」는 pdfplumber(0.18초/쪽).
   전 페이지를 pdfplumber 로 돌릴 이유가 없다.

## 9. HTTP Range 로 「다운로드 없이 열기」는 **이득이 없다** (2026-09-07)

전부 Linearized(웹 최적화) PDF 라 조건은 완벽했다. `seek`/`read` 를 Range 요청으로 바꾸는 파일 객체를
만들어 pypdf 에 물려 봤다.

| | 삼성전자 4.0MB | NAVER 80.8MB |
|---|---|---|
| Range | 1.0초 · **35요청** · 2.27MB(56%) | 7.9초 · **250요청** · 16.4MB(20%) |
| 통짜 GET | **0.4초** | **6.9초** |

바이트는 80%까지 아끼는데 **시간은 더 걸린다**. 파서가 여는 순간 20~56%를 끌어오고, 왕복 250번은
「간격 0.5초」 예의 규칙과도 충돌한다(그대로 지키면 125초).

→ 통짜로 받고 텍스트만 남긴 뒤 바이트는 버린다.

## 10. 벤치마크 1위 파서가 우리 문서에선 수치표를 못 잡는다 (2026-09-07)

OpenDataLoader(Apache-2.0, opendataloader-bench 0.907/표 0.928 1위)를 실제로 돌렸다. 서술형 표는
**훌륭한 마크다운 표**로 복원했다 — 이해관계자 소통표를 4열로 정확히.

그런데 검출한 표 31개가 **전부 5~60쪽**이고, **수치가 다 있는 70~80쪽엔 0개**였다. 게다가 빈 칸을
조용히 버린다:

```
원문      제품 에너지 사용량 절감률  %  16.4  -  25.1  -  31.5  -    (DX/DS × 3년 = 6열)
ODL       제품 에너지 사용량 절감률  %  16.4     25.1     31.5       (- 3개 소실)
```

값 3개만 남으니 「16.4=2022」처럼 보이지만 실제 열은 DX/DS 교차다. **값↔열 대응이 무너진다.**
결정적으로 `java -jar` 로 24MB JAR 을 띄운다(실험하려고 94MB JRE 를 따로 깔아야 했다).

→ 배제. **벤치마크 순위는 우리 문서에 대한 보증이 아니다** — 영문 논문·재무제표 기준이다.

## 11. 표 격자는 좌우 2단 조판에서 숫자가 갈라진다 (2026-09-07)

pdfplumber 의 글자 정렬 전략으로 격자를 뽑으면 **왼쪽 표는 완벽**하다:

```
재생에너지 전환율 | % | 93.1 | 23.2 | 93.4 | 24.3 | 93.4 | 24.8
```

같은 페이지 오른쪽 표는:

```
폐기물 발생량 | 톤 | 329,861 | 1,083,504 |  | 3 | 07,325 | ...
                                              ↑ 307,325 가 두 칸으로
재활용       | 톤 | 308,670 | 1,055,697 | 28 | 4,484 | ...
```

「폐기물 처리량」도 `폐` + `기물 처리량` 으로 쪼개진다. 한 페이지 안에서 **한쪽은 맞고 한쪽은 틀린데
호출자는 구분할 수 없다.**

수치 구역 11쪽·값 605개로 재보니 **격자 97.4% · 정렬 텍스트 100%** 보존이었다.

→ 격자는 `table=True` **opt-in** 으로만. 그리고 고칠 수 없으니 **짚어는 준다**: 격자 칸의 숫자가
   평문(pypdfium2, 숫자 깨짐 0) 토큰에 없으면 쪼개진 조각이다 → `⚠` 표시.
   이 신호가 유실을 잘 예측한다(의심 0인 6쪽은 유실 0, 의심 20인 74쪽은 유실 10).

## 12. GIR 과 보고서는 **범위만 맞추면 같은 값**이다 (2026-09-08)

「검증 규제치 vs 자발적 공시치라 다를 것」이라고 적어 뒀는데, 5개사로 대조해 보니 반대였다.

| 회사 | GIR 명세서 | 보고서에서 같은 범위 | 차이 |
|---|---|---|---|
| 포스코홀딩스(별도) | 10,745 | **10,746** | **1톤** (2022·2023 은 완전 일치) |
| 현대차 | 1,526,375 | **1,526,385** | **10톤** |
| SK하이닉스 | 4,848,541 | **4,843,611** | 0.10% |
| LG화학 | 8,351,819 | **8,310,445**(국내) | 0.50% |
| 삼성전자 | 13,594,735 | ≈14,890,000(글로벌) | 9% ← **범위가 다르다** |

회사가 GIR 에 낸 명세서를 보고서에도 싣기 때문이다 — 현대차 검증의견서(p139)가 「배출권거래제 배출량
보고 및 인증에 관한 지침」을 그대로 명시한다. 현대차 헤드라인 2,097,809 는 「국내 전 사업장 + 해외
11개 법인」이고, 해외 11개 공장 합계 571,424 를 빼면 GIR 과 10톤 차이다.

→ 할 일은 「차이 보여주기」가 아니라 **「범위 밝혀 주기」**였다. 축 셋: 경계 · Scope 2 방식 · NF3 포함 여부.

## 13. 한 보고서 안에 같은 해 값이 **셋** 있다 (2026-09-08)

SK하이닉스 2024년 Scope 1+2:

| 쪽 | 값 | 범위 |
|---|---|---|
| p87 검증의견서 | 4,843,611 | 국내 · 지역기반 · NF3 제외 → **GIR 과 일치** |
| p72 | 5,502,136 | 글로벌 · 시장기반 |
| p87 합계 | 5,717,404 | 국내 + NF3 873,793 |

「SK하이닉스 2024년 배출량이 얼마냐」에 숫자 하나로 답하면 **셋 중 둘은 틀린다.**

→ 값을 필드로 만들지 않는다. 원문 발췌 + 범위 축을 주고 판단은 넘긴다.
   범위를 못 밝힌 발췌는 빈 `basis` 로 두고 「이 발췌만으로 GIR 과 비교하지 말 것」이라고 적는다.

## 15. 「Scope 1+2」를 「Scope 1」로 세고 있었다 (2026-09-08)

테스트를 쓰다가 잡았다. `Scope\s*1` 정규식이 「Scope 1+2 합계」 안에서도 매치된다 —
2,097,809 를 Scope 1 값으로 읽으면 **세 배 가까이 틀린다**(실제 Scope 1 은 679,822).

→ 넓은 종류가 차지한 자리를 막는다. 단, 같은 표의 **별도** Scope 1 행은 살아 있어야 해서
   회귀 테스트로 못 박았다(현대차 p115 는 넷 다 잡혀야 정상).

## 16. 등급 백분위는 만들 수 없다 — 동점이 30~60% (2026-09-08)

「KCGS 기준 상위 12%」 같은 걸 주려다 분포를 세어 봤다(2025년 795사).

| 기관 | 평가 대상 | 최다 등급 동점 |
|---|---|---|
| 한국ESG연구소 | 198사 | A 에 **120사(61%)** |
| 서스틴베스트 | 198사 | BB 에 72사(36%) |
| KCGS | 782사 | D 에 225사(29%) |
| MSCI | **74사(9%)** | A 에 20사(27%) |

등급이 6~7단계뿐이라 한국ESG연구소 A 등급은 「상위 6%」일 수도 「상위 67%」일 수도 있다.
그리고 **MSCI 는 795사 중 74사만** 평가한다(대형주 위주) — 「MSCI 기준 상위 20%」는 전체 상장사가
아니라 그 74사 중 20%다.

→ 백분위를 만들지 않고 **세어서 그대로** 준다: 「이 등급 이상 N사(%) · 동점 M사 · 분포」.
   효용은 바로 나온다 — 삼성전자 서스틴베스트 `B` 는 「이 등급 이상 88.4%」다. 등급만 봐선 모른다.

## 17. 업종 체계가 셋인데 이름이 다 다르다 (2026-09-08)

산업군별로 보려고 KRX 지수 포털의 GICS 분류를 붙였더니, 이미 있던 분류 둘과 겹치지 않았다.

|---|---|---|
| GICS 산업군(25개) | 하드웨어및IT장비 | KRX 지수 포털 — S&P·MSCI 기준 |
| 포털 업종(21개) | 전기·전자 | 지속가능경영보고서 목록 필터 |
| GIR 지정업종 | 반도체 제조업 | 온실가스 명세서(규제 목적) |

셋 다 「업종」이라고 부르는데 한 표에 섞으면 회사가 세 곳에 나타난다.

→ 응답마다 어느 체계인지 밝히고, GICS 에는 고지를 붙였다. `esg_screener` 는 두 필터
   (`industry` 포털 업종 · `gics_group` GICS)를 따로 받는다.

**곁들여 알게 된 것:** 지수 포털은 ESG 포털·KIND 와 **또 다른 호스트**(`index.krx.co.kr`)이고
**OTP 토큰 + 쿠키**가 필요하다 — `GenerateOTP.jspx` 로 code 를 받아 `IDX99000001.jspx` 에 실어 보낸다.
조회 때마다 두드릴 물건이 아니라 스냅샷으로 동봉했다(2,534종목 328KB).

검증: 유건호 리서치가 2026-08-04 에 뽑아 둔 CSV(KOSPI 829행)와 대조해 **불일치 0건**이었다.

## 18. 산업군 안에서 보면 등급이 달리 보인다 (2026-09-08)

삼성전자 서스틴베스트 `B` 등급:

```
전체 198사 중   이 등급 이상 175사 (88.4%)
산업군 안 6사 중 이 등급 이상   6사 (100%)   ← 그 산업군 최하위
```

반대로 KCGS `A` 는 전체 26.5% 인데 산업군(하드웨어및IT장비 28사) 안에서는 17.9% 로 더 위다.
**비교군을 바꾸면 결론이 바뀐다** — 그래서 둘 다 보여주고 어느 쪽인지 밝힌다.

산업군은 표본이 작아 동점 영향이 더 크므로 평가 대상 5사 미만이면 아예 싣지 않는다.

## 환경에서 겪은 것

- **회사망 TLS 가로채기.** `curl` 은 `--ssl-no-revoke` 가 필요했고, `httpx` 는
  `CERTIFICATE_VERIFY_FAILED: self-signed certificate in certificate chain` 로 막혔다.
  Windows 인증서 저장소를 `ssl.enum_certificates` 로 얹어 **검증을 켠 채** 우회했다
  (`scripts/smoke_kind.py`).
- **KIND 는 HEAD 에 405 를 준다.** 파일 크기를 물어보려면 `Range: bytes=0-0` 으로 1바이트를 받고
  `Content-Range` 의 총량을 읽어야 한다.
- **첨부 PDF 크기 편차가 20배다**: 삼성 4.0MB · LG화학 6.0MB · 포스코홀딩스 7.7MB ·
  SK하이닉스 10.4MB(국·영문 2건) · 현대차 56.9MB · **NAVER 80.8MB**. 셀트리온은 첨부가 없다
  (회사 사이트에만 올린 경우 — 「안 냈다」가 아니다).
- **KRX 지수 포털은 OTP·쿠키를 요구한다.** `GenerateOTP.jspx` → `IDX99000001.jspx` 순서를 지켜야 하고,
  쿠키를 물고 다녀야 한다. ESG 포털(`esg.krx.co.kr`)·KIND(`kind.krx.co.kr`)와 같은 거래소인데 방식이 다 다르다.
- **삼성전자 지배구조 준수율은 3년 내리 86.7%**(13/15)였다. 미준수 둘도 같다 —
  「현금 배당관련 예측가능성 제공」·「집중투표제 채택」.

## 되풀이되는 교훈

1. **문서보다 응답을 믿는다.** 핸드오프의 「비고에 사유가 있다」·「DART 링크도 열린다」가 둘 다 틀렸다.
2. **0건은 「없음」이 아니라 대개 「못 읽음」이다.** 자간 공백·서식 변경·차단이 전부 0건으로 나타난다.
   응답 문구에서 이 둘을 구분하지 않으면 조용히 틀린 답이 나간다.
3. **고칠 수 없으면 짚어라.** 격자의 쪼개진 숫자, 범위 불명 발췌, 동점 등급 — 정확히 만들 수 없는 것은
   경고를 붙여 내보내는 편이 안 주는 것보다도, 그럴듯하게 주는 것보다도 낫다.
4. **벤치마크는 남의 문서 기준이다.** 1위 파서가 우리 수치표에선 0개를 잡았다.
5. **테스트가 버그를 잡는다.** 「Scope 1+2」오독은 테스트를 쓰다가 나왔다. 실호출만 보고 있었으면
   숫자가 그럴듯해서 넘어갔을 것이다.
